## C. Telegram 来源与任务投递

### 12. 同步入口如何设计？

推荐：保留“同步全部已绑定来源”，同时在每个来源行增加“只同步此来源”；本阶段不做后台定时自动同步，避免静默漏错和 Telegram 风控。

你的回答：采用推荐

### 13. 消息怎样进入工具？

推荐：同步成功后自动过滤并创建对应工具任务；只有提取到至少一条有效结果才创建任务。同步完成提示直接列出新任务，并提供“打开刚生成的任务”。

你的回答：采用推荐

### 14. 原 Telegram 消息如何标记？

推荐：个人 API 来源增加“成功后标为已读”开关，默认开启；只有该来源绑定的所有工具都保存成功后，才将 Telegram 中截至最高已处理消息标为已读。该操作仅影响你的账号，不在群里留下公开痕迹。

可选方案：自动添加 `✅` 反应，但所有群成员可见，且可能触发权限或频率限制，因此不建议默认使用。Bot 来源只能推进 Bot 更新 offset，不能替你的个人账号标为已读。

你的回答：采用推荐

### 15. 多工具投递中途失败怎么办？

推荐：先在一个本地事务中保存全部工具任务，再推进来源检查点；任一工具保存失败就不推进检查点、不标为已读，并进入“同步异常”队列供重试。依靠 Telegram 消息 ID 去重，避免重试产生重复任务。

你的回答：采用推荐

### 16. 首次回拉历史如何限制？

推荐：绑定来源时必须明确选择“从现在开始”或“按时间回拉”；历史回拉要求填写起止时间或最大消息数，默认最多 2,000 条，用户可提高到 20,000 条并看到警告。

你的回答：采用推荐

### 17. API、Bot、文件导入如何去重？

推荐：个人 API/Bot 使用“来源 ID + 消息 ID”去重；Telegram 官方导出文件尽量使用群组 ID/名称、消息 ID和时间建立跨入口去重。无法可靠识别同一来源时只警告，不擅自丢消息。

你的回答：采用推荐
