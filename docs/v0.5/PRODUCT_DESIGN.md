# TG 内容工具箱 v0.5 产品设计

状态：阶段 0 已落地，尚不是日常使用版

分支：`codex/v0.5-redesign`

更新时间：2026-07-26

## 1. 为什么重构

v0.4.5 已积累大量功能，但输入、网站查询、账号操作、同步、数据库和异常处理互相牵连。继续在旧页面加板块，会让操作路径更长、界面更卡，错误也更难定位。

v0.5 不按旧界面翻新，而是按以下原则重新建立产品：

1. 工具优先：打开首页先选择要做什么，不先理解批次、数据库和任务槽。
2. 一次一件事：每个工具只展示输入、当前执行、结果与本工具历史。
3. 数据表统一：所有记录管理使用同一套表格交互，不再为每页重复实现半套增删改查。
4. 任务持久化：长任务是数据库中的真实状态，不依赖某个页面保持打开。
5. 网站隔离：不同网站可并行；同一网站由自己的队列、速度和错误策略控制。
6. 迁移可审计：先只读检查旧库，再备份、预览、确认、迁移；任何一步失败都可回退。
7. 先小工具、后影片链路：先用海角工具证明新架构，再迁移推特、Bad.news、MissAV；123AV 最后单独重做。

## 2. 用户看到的结构

```text
工具首页
├─ 海角链接
│  ├─ 新任务
│  ├─ 当前结果
│  └─ 处理历史
├─ 推特博主
├─ Bad.news
├─ MissAV
└─ 123AV（重构前继续使用 v0.4.5）

公共能力
├─ 可靠任务中心
├─ 统一数据表
├─ Telegram 来源
├─ Raindrop 同步
└─ 设置、日志与备份
```

工具首页只放入口和简短状态，不把所有配置堆进侧边栏。进入工具后再显示该工具的步骤。

## 3. 标准工具流程

每个文本工具共享骨架，但过滤规则、历史记录和来源绑定彼此独立：

1. 选择输入：粘贴文本、多文件导入或一个/多个 Telegram 群组与频道。
2. 可选时间范围：精确到分钟。
3. 生成预览：显示总消息、命中、去重、过滤与警告数量。
4. 确认保存：结果写入本工具历史；原始全文默认不进入永久库。
5. 结果页：搜索、选择、编辑、删除、复制、导出和回看来源摘要。

MissAV 在此基础上追加：网站查询、标签清洗、永久番号库、Raindrop 手动同步。123AV 保持独立查询和账号操作，不与 MissAV 自动串联。

## 4. 技术边界

| 层 | 选择 | 责任 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 / WebView2 | Windows 窗口、系统文件选择、打包 |
| 前端 | Vue 3 + TypeScript | 工具页面、状态展示、交互编排 |
| 表格 | Tabulator | 虚拟渲染、选择、编辑、分页与导出 |
| 本地服务 | Rust | 命令白名单、任务调度、数据库与迁移 |
| 数据库 | SQLite + WAL + FTS5 | 主数据、全文搜索、任务检查点与历史 |

前端不能直接执行任意 SQL，只能调用经过校验的 Rust 命令。正式数据操作必须有事务、外键、唯一约束和必要备份。

新应用位于 `apps/desktop-v05`，标识为 `com.wjl.tg-content-toolbox.next`。它与根目录 Electron v0.4.5 同仓共存，但使用不同的运行目录和数据库。

## 5. 统一数据模型方向

正式模型将在阶段 1 后固化，核心对象包括：

- `tools`：工具注册和能力声明；
- `sources`：文件、Telegram 群组、频道及其断点；
- `tasks` / `task_items`：可恢复任务与逐项状态；
- `records`：统一结果主记录；
- `record_tags`：标签关系；
- `runs`：一次处理的输入摘要、规则版本和统计；
- `remote_mappings`：Raindrop 等远端对象映射；
- `audit_events`：重要编辑、删除、迁移和同步证据。

工具私有字段使用明确的扩展表或版本化 JSON；不把所有字段塞入一个无法约束的大 JSON。

## 6. 任务与错误策略

任务状态至少包含：等待、运行、暂停、完成、取消。每个项目保存等待、运行、成功、失败或取消状态。

- 启动任务前落库；
- 每完成一项就提交检查点；
- 应用退出时仍为运行中的任务，下次启动自动改为暂停；
- 运行中的项目恢复为等待，避免永久卡死；
- 恢复时从未完成项继续，不重跑已经确认成功的项目；
- 网站限速、网络错误、验证页和业务未找到必须分开记录。

阶段 0 的任务原型已经验证这些基础语义，具体网站重试策略在迁移相应工具时添加。

## 7. 旧库迁移方案

迁移分四步：

1. 只读分析：`SQLITE_OPEN_READ_ONLY` 和 `PRAGMA query_only=ON`；输出完整性、表规模和候选映射。
2. 自动备份：复制正式库、WAL 和必要配置并生成校验信息。
3. 预演迁移：写入全新的 v0.5 数据库，输出新增、合并、跳过、冲突和失败报告。
4. 人工确认：只有报告通过后才切换；旧库始终保留，可一键回退。

阶段 0 只实现第 1 步。没有任何正式迁移入口。

## 8. 分阶段交付

| 阶段 | 目标 | 放行条件 |
| --- | --- | --- |
| 0 | 壳、10 万行表格、可靠任务、只读迁移报告 | 编译、单测、真实窗口与负载验证通过 |
| 1 | 海角完整流程 | 文件/TG 输入、分钟范围、预览、历史、导出可用 |
| 2 | 推特与 Bad.news | 各自规则和历史独立，复用统一底座 |
| 3 | MissAV | 查询、标签、永久库和 Raindrop 手动同步稳定 |
| 4 | 123AV | 查询与账号操作独立，站点级限速和异常恢复 |
| 5 | 正式迁移与 Windows 发布 | 净机测试、迁移回退和发布包验收通过 |

任何阶段未通过验收，都继续使用 v0.4.5，不提前替换主线 EXE。
